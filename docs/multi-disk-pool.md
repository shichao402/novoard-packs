# 一个工作副本池使用多个硬盘

池根负责管理，槽位负责存放工程。配置、状态、分支入口和 patch 存档仍在一个池根；槽位可以散布在多个本机硬盘的专用目录。

## 配置

```toml
maxSlots = 4
svnRoot = "https://svn.example.com/project"
defaultTtl = "1d"
resident = ["trunk", "release"]
patchRetentionDays = 30

[aliases]
trunk = "trunk"

[branches]
pattern = "branches/{name}"
listFrom = ["branches"]
recentDays = 30

[storage]
# 仅用于新槽位；不必包含旧槽位所在的盘。
# 必须是已经创建的本机绝对目录，不使用盘根、项目目录或网络共享。
roots = ["D:/pool-slots", "F:/pool-slots"]
# 每次新建前要求的最低可用空间，单位 GiB，非负整数。
minFreeGiB = 700
```

已有池只需改顶层 `maxSlots` 并在文件末尾添加 `[storage]`，保留已有仓库、分支与稀疏配置。不要把 `maxSlots` 写进 `[storage]`。

先创建各个专用目录。工具不会自动创建 `roots`，避免拼错目录或磁盘未挂载时把大量内容写到错误位置。

`roots` 是新建位置的候选集合，不是“第一个根分配 s01、第二个根分配 s02”的固定映射。池挑剩余空间最多的合格目录，空间相同则按配置顺序。所有候选都不可访问、空间不够或存在同名内容时，新建失败并列出原因，不回退到未配置的磁盘。

## 现有槽位不搬动

例如池根 `E:/pool` 原有 s01、s02：

- 旧记录没有 `path` 时仍使用 `E:/pool/slots/s01`、`s02`，不改记录或目录。
- 新建 s03 时将选中的实际绝对路径记入 `.pool/state.json`，如 `D:/pool-slots/s03`。
- 新建 s04 时重新检查候选位置与剩余空间，不保证一定换一块盘。
- 修改或删除 `[storage].roots` 只影响后续新建，不迁移、不丢弃已有槽位，也不改变它们的分支。

每个新槽位都记录 `path`，即使它使用缺省的 `<池根>/slots`。路径一旦记录，命中、切换、更新、缩容和中断恢复都使用它。

分支入口仍为 `<池根>/branch/<分支>`，直接指向实际槽位目录；Windows 使用 junction，其他平台用目录符号链接。无需在 `<池根>/slots` 下为外置槽位额外建占位链接。

`status` 的人读结果和结构化 `pool.slots[].path` 会显示每个槽位位于哪个实际目录，`acquire` 的结果同样包含实际目录。dry-run 仅打印候选根与准入阈值，不分配槽位、不创建目录、不检查远端分支。

## 空间和并发边界

`minFreeGiB` 是检出开始前的准入阈值，不是 SVN 工程大小估算，也不是“检出完成后保证保留多少空间”。请按完整工程、SVN 原始副本、构建产物和编辑器缓存设置足够的余量。

同一池并发新建时，在池状态锁内按 `minFreeGiB` 对正在新建的槽位保守预留；同一文件系统下多个候选目录共用这份预留。分配后、检出前还会重新检查实际剩余空间。其他池、其他应用或检出过程中的后续增长不由本池预留保证，磁盘仍可能在运行期间耗尽。

不写 `[storage]` 时兼容旧配置：新槽位使用 `<池根>/slots`，`minFreeGiB` 缺省为 0。也可以只写 `[storage] minFreeGiB` 来给原盘增加准入门槛。配置了 `roots` 时不能为空。

## 安全与恢复

- 不覆盖任何已有同名目录、文件或链接，包括断链，也不把新槽位放入池的状态、分支入口、patch 存档或另一个槽位内部。
- 新建采用 exclusive mkdir。分配后其他进程抢建同名目录时，失败返回，不清理对方的目录。
- 成功创建目录后在操作记录中写入 `op.created`；中断恢复不能确认目录所有权时保留目录与记录，报告需要人工检查，不自动解除阻塞。
- 外置槽位父目录不可访问时，命中与切换失败，缩容和恢复保留槽位并报告存储不可访问，不按普通“工作副本缺失”删除记录，也不悄悄在其他盘重建。
- 缩容删除只作用于状态记录的槽位目录，不删 storage 根目录或同级其他目录。已有受控改动仍先存档，租约和常驻规则不变。
- `path` 由池写入，不是手工修改状态来搬迁工程的接口。绝对路径必须以自己的槽位编号结尾。
- 已使用外置槽位的池不能交给不支持 `path` 的旧版包运行：旧版会按旧目录模型解析。回退前必须先完成显式迁移，不能只删 `[storage]`。

## 验证

```powershell
npm run typecheck
npm test
npm run build
```

`tests/working-copy-pool-storage.test.ts` 覆盖配置校验、空间选择、同盘并发预留、旧路径兼容和目录保护；`tests/working-copy-pool-storage.integration.test.ts` 用 `svnadmin` 建临时 `file://` 仓库，验证池根以外的真实检出、切换、更新、清理、缩容与中断恢复。集成测试的两个 storage 根是临时目录，不是大型工程的跨物理盘容量测试。

2026-11-23 Windows 实机另用极小临时 SVN 工程验证了 D、F 两个物理盘上的检出、固定槽位路径、跨盘 junction 与定向回收；测试临时目录已清理，没有迁移真实工程。
