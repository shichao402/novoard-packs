# 一个工作副本池使用多个硬盘

池定义目录负责管理，槽位负责存放工程。配置、状态、分支入口和 patch 存档在池定义目录；槽位只放在 `[storage].roots` 列出的本机专用目录里，可以散布在多个硬盘。池定义目录里不放槽位，也没有 `slots/` 目录。

槽位对用户不可见：日常通过 `<池定义目录>/branch/<分支>` 这个稳定入口或 Launcher 打开工程；必须用真实路径打开的程序由 Launcher 代理，用户不需要记住某个分支在哪个槽位、哪块盘上。

## 配置

```toml
maxSlots = 4
svnRoot = "https://svn.example.com/project"
defaultTtl = "1d"
# 当前需要的工作分支（工程清单）；Launcher 按它生成工程卡片
projects = ["release", "feature-x"]
patchRetentionDays = 30

[branches]
pattern = "branches/{name}"
listFrom = ["branches"]
recentDays = 30

[storage]
# 必填。允许放槽位的目录：本机绝对目录，事先创建好，不用盘根、网络共享，也不能在池定义目录里面。
# 每项可以是字符串，也可以写成 { path, minFreeGiB } 给这块盘单独设下限。
roots = ["D:/pool-slots", { path = "F:/pool-slots", minFreeGiB = 300 }]
# 没有单独设下限的目录用这个值，单位 GiB，非负整数，缺省 0。
minFreeGiB = 700
```

先创建各个专用目录。工具不会自动创建 `roots`，避免拼错目录或磁盘未挂载时把大量内容写到错误位置。同一目录重复出现时下限必须一致，否则报错。

`roots` 是新建位置的候选集合，不是“第一个根分配 s01、第二个根分配 s02”的固定映射。池挑剩余空间最多、且满足该目录自己下限的位置，空间相同则按配置顺序。所有候选都不可访问、空间不够或存在同名内容时，新建失败并列出每个目录的原因，不回退到未配置的磁盘。

trunk 这类每天都要用的分支不进池：池里没有“常驻”概念，它们作为手动管理的工作副本放在池外，由 Launcher 单独建卡片。

## 槽位路径固定

- 新建槽位时把实际绝对路径记入 `.pool/state.json` 的 `path`，如 `D:/pool-slots/s03`。之后命中、切换、更新、缩容和中断恢复都用这个路径。
- 新建 s04 时重新检查候选位置与剩余空间，不保证一定换一块盘。
- 修改或删除 `[storage].roots` 只影响后续新建，不迁移、不丢弃已有槽位，也不改变它们的分支。
- 状态里没有 `path` 的槽位直接报错，提示先迁移；不再回退到池定义目录里的 `slots/`。

分支入口为 `<池定义目录>/branch/<分支>`，直接指向实际槽位目录；Windows 用 junction，其他平台用目录符号链接。入口只在分支挂在槽位上、槽位目录存在时才有：分支被换出、目录被删、槽位被池外切到别的分支后，入口随之删除或改指，不留失效路径。

`status` 的人读结果和结构化 `pool.slots[].path` 显示每个槽位的实际目录，`pool.projects` 是工程清单，`pool.storage` 是存储配置；`acquire` 的结果同样包含实际目录。dry-run 只打印候选目录与各自下限，不分配槽位、不创建目录、不检查远端分支。

## 从旧布局迁移

旧池的槽位在 `<池定义目录>/slots/sNN`（可能本身就是指向别的盘的 junction）。新版包不再识别这种布局，升级前按下面的顺序迁移，迁移期间不要运行池的工具：

1. 对每个槽位确认真实目录（`slots/sNN` 是 junction 时取它的目标），写进 `state.json` 对应槽位的 `path`。
2. 把这些真实目录的父目录加进 `[storage].roots`，并按盘设好 `minFreeGiB`。
3. 删除 `<池定义目录>/slots` 下的 junction 和空目录；只删链接，不动真实工作副本。
4. 把 `resident` 改成 `projects`，并把 trunk 这类日常分支移出池。
5. 换上新版包后跑一次 `gc`，它会校正记录并同步 `branch/` 入口。

## 空间和并发边界

`minFreeGiB` 是检出开始前的准入阈值，不是 SVN 工程大小估算，也不是“检出完成后保证保留多少空间”。请按完整工程、SVN 原始副本、构建产物和编辑器缓存设置足够的余量。

同一池并发新建时，在池状态锁内对正在新建的槽位按其所在目录的下限保守预留；同一文件系统下多个候选目录共用这份预留。分配后、检出前还会重新检查实际剩余空间。其他池、其他应用或检出过程中的后续增长不由本池预留保证，磁盘仍可能在运行期间耗尽。

## 安全与恢复

- 不覆盖任何已有同名目录、文件或链接，包括断链，也不把新槽位放入池定义目录（配置、入口、patch 存档）或另一个槽位内部。
- 新建采用 exclusive mkdir。分配后其他进程抢建同名目录时，失败返回，不清理对方的目录。
- 成功创建目录后在操作记录中写入 `op.created`；中断恢复不能确认目录所有权时保留目录与记录，报告需要人工检查，不自动解除阻塞。
- 槽位所在的存储目录不可访问（如盘未挂载）时，命中与切换失败，缩容和恢复保留槽位并报告存储不可访问，不按“目录已删”移除记录，也不悄悄在其他盘重建。
- 存储目录可访问但槽位目录已被删：没有持有保护就移除记录，有保护就标为阻塞，解除保护后下次运行移除。
- 槽位被人在池外 `svn switch` 到别的分支：按实际分支更新记录与入口；该分支已在别的槽位上时标为阻塞，切回原分支后 `gc` 解除。
- 缩容删除只作用于状态记录的槽位目录，不删 storage 根目录或同级其他目录。已有受控改动仍先存档。
- `path` 由池写入，不是手工修改状态来搬迁工程的接口；只有上面的一次性迁移需要手工写。绝对路径必须以自己的槽位编号结尾。

## 验证

```powershell
npx tsc --noEmit -p .
npx vitest run
npm run build
```

`tests/working-copy-pool-storage.test.ts` 覆盖配置校验、每盘下限、空间选择、同盘并发预留、缺 `path` 的迁移报错和目录保护；`tests/working-copy-pool-storage.integration.test.ts` 用 `svnadmin` 建临时 `file://` 仓库，验证池定义目录以外的真实检出、切换、更新、清理、缩容与中断恢复。集成测试的两个 storage 根是临时目录，不是大型工程的跨物理盘容量测试。
